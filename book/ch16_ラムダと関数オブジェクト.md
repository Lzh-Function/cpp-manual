# 第16章 ラムダと関数オブジェクト

Pythonの `lambda` とC++のラムダは、見た目は似ていますが**中身が全く違います**。
C++のラムダは非常に強力で、しかも速いです。

## 16.1 基本形

```python
f = lambda x: x * 2
sorted(mols, key=lambda m: m.mw)
```

```cpp
auto f = [](double x) { return x * 2; };
std::sort(mols.begin(), mols.end(),
          [](const Mol& a, const Mol& b) { return a.mw < b.mw; });
```

構文:

```
[キャプチャ](引数リスト) -> 戻り値型 { 本体 }
 ↑          ↑              ↑（省略可）  ↑
 外の変数を  普通の関数と同じ  推論される   複数文書ける
 取り込む
```

> 💡 **Pythonのラムダは1つの式しか書けませんが、C++のラムダは
> 何行でも書けます。** 実質的に「その場で定義する無名関数」です。

```cpp
auto complex_filter = [](const Molecule& m) {
    if (m.mw > 500) return false;
    int violations = 0;
    if (m.logp > 5) ++violations;
    if (m.hbd > 5) ++violations;
    return violations <= 1;
};
```

## 16.2 ★キャプチャ★ — 外の変数を使う

これがC++ラムダの核心です。

```cpp
double threshold = 0.7;

auto is_similar = [threshold](double score) { return score > threshold; };
//                 ^^^^^^^^^ キャプチャリスト
```

### キャプチャの種類

```cpp
int a = 1, b = 2;

[ ]         // 何もキャプチャしない
[a]         // a を「コピー」でキャプチャ
[&a]        // a を「参照」でキャプチャ
[a, &b]     // a はコピー、b は参照
[=]         // 使っている変数を全部コピー（非推奨）
[&]         // 使っている変数を全部参照（注意して使う）
[=, &b]     // b だけ参照、他はコピー
[&, a]      // a だけコピー、他は参照
[this]      // クラスのメンバ関数内で、this をキャプチャ
[*this]     // オブジェクト自体をコピー（C++17）
[x = expr]  // 初期化キャプチャ（C++14）。新しい変数を作る
```

### コピーキャプチャ

```cpp
double threshold = 0.7;
auto f = [threshold](double s) { return s > threshold; };   // 0.7 がコピーされる
threshold = 0.9;
f(0.8);   // ★ true。ラムダは 0.7 を持ったまま
```

```
   ラムダオブジェクト（実体はクラス）
   +---------------------+
   | threshold = 0.7     |   ← 作成時点の値をコピーして保持
   | operator()(double)  |
   +---------------------+
```

### 参照キャプチャ

```cpp
double threshold = 0.7;
auto f = [&threshold](double s) { return s > threshold; };
threshold = 0.9;
f(0.8);   // ★ false。ラムダは現在の threshold を見る
```

> ⚠️ **参照キャプチャのダングリング**
>
> ```cpp
> std::function<bool(double)> make_filter() {
>     double threshold = 0.7;
>     return [&threshold](double s) { return s > threshold; };
>     // ★ threshold は関数を抜けたら消える → ダングリング参照
> }
> ```
>
> **ラムダが元のスコープより長生きするなら、必ずコピーキャプチャ**してください。
>
> 目安:
> - **その場で使い切る**（`std::sort` の比較関数など）→ `[&]` でよい。速い
> - **保存する / 別スレッドに渡す** → コピーキャプチャ

### 初期化キャプチャ（C++14）

```cpp
// ムーブしてキャプチャする（unique_ptr など）
auto ptr = std::make_unique<Molecule>("CCO");
auto f = [p = std::move(ptr)]() { return p->num_atoms(); };

// 計算結果をキャプチャ
auto g = [n = compute_expensive()](double x) { return x * n; };

// メンバをコピーしてキャプチャ（this のダングリング回避）
auto h = [threshold = this->threshold_](double s) { return s > threshold; };
```

### `[=]` と `[&]` の是非

```cpp
[=]   // 「全部コピー」— 何をキャプチャしているか分からない。重いオブジェクトも入る
[&]   // 「全部参照」— ダングリングの危険
```

> 💡 **推奨: キャプチャは明示的に書く。**
> ```cpp
> [threshold, &results]   // ✓ 何を使っているか一目瞭然
> ```
> ただし、`std::sort` の比較関数のようにその場で使い切るものは
> `[&]` でも実害はありません。チームのルールに従ってください。

### this のキャプチャ（罠）

```cpp
class Screener {
    double threshold_ = 0.7;
public:
    auto make_filter() {
        return [this](double s) { return s > threshold_; };   // ★ this をキャプチャ
    }                                                          //   Screener が死ぬと危険
};
```

`[=]` を書いても、**メンバ変数はコピーされません**（`this` がコピーされるだけ）。
これは混乱の元なので、C++20 では `[=, this]` と明示するよう推奨されています。

安全にしたいなら:

```cpp
return [threshold = threshold_](double s) { return s > threshold; };   // ✓ 値をコピー
// または C++17
return [*this](double s) { return s > threshold_; };                    // オブジェクトごとコピー
```

## 16.3 ラムダの正体: 関数オブジェクト

**C++のラムダは、コンパイラが自動生成する「クラス」です。**

```cpp
double threshold = 0.7;
auto f = [threshold](double s) { return s > threshold; };
```

これは、コンパイラが以下のようなクラスを裏で作っているのと同等です:

```cpp
class __lambda_1 {
    double threshold;                                  // キャプチャした変数
public:
    explicit __lambda_1(double t) : threshold(t) {}
    bool operator()(double s) const { return s > threshold; }   // 関数呼び出し演算子
};

__lambda_1 f(threshold);
f(0.8);      // f.operator()(0.8) が呼ばれる
```

**ここが重要:**

1. **ラムダはそれぞれ固有の型を持つ**（同じコードでも別の型）
2. **`operator()` は普通のメンバ関数なので、インライン展開される**
3. **仮想関数ではないので、オーバーヘッドがゼロ**

```cpp
auto f = [](int x) { return x; };
auto g = [](int x) { return x; };
// f と g は【違う型】。std::is_same_v<decltype(f), decltype(g)> == false
```

### だからラムダは速い

```cpp
std::sort(v.begin(), v.end(), [](int a, int b){ return a < b; });
```

`std::sort` はテンプレートなので、このラムダ型専用の `sort` が生成され、
**比較関数がインライン展開されます**。

一方、C の `qsort` は関数ポインタを取るので、
毎回**間接呼び出し**が発生し、インライン展開できません。

```
std::sort + ラムダ : 比較がインライン展開される → 速い
qsort + 関数ポインタ : 毎回間接呼び出し        → 遅い（2〜3倍）
```

**これがC++の「抽象化はタダ」の実例です。**

## 16.4 mutable ラムダ

```cpp
auto counter = [n = 0]() mutable { return n++; };
std::cout << counter() << counter() << counter();   // 012
```

デフォルトでは、ラムダの `operator()` は `const` です。
つまりコピーキャプチャした変数を変更できません。
`mutable` を付けると変更できるようになります。

```python
# Python の nonlocal に近い
def make_counter():
    n = 0
    def counter():
        nonlocal n
        n += 1
        return n - 1
    return counter
```

## 16.5 戻り値型の指定

```cpp
auto f = [](double x) { return x > 0 ? x : 0; };     // double が推論される

auto g = [](int x) -> double {                        // 明示的に指定
    if (x == 0) return 0;      // int の 0 だが、double に変換される
    return 1.0 / x;
};
```

**複数の `return` で型が違う場合は、明示が必要**です:

```cpp
auto bad = [](bool b) {
    if (b) return 1;      // int
    else   return 1.0;    // double  ★ エラー: 戻り値型が一致しない
};

auto good = [](bool b) -> double {
    if (b) return 1;
    else   return 1.0;
};
```

## 16.6 ジェネリックラムダ（C++14 / C++20）

```cpp
auto print = [](const auto& x) { std::cout << x << "\n"; };
print(42);
print("hello");
print(3.14);
```

`auto` 引数のラムダは、**テンプレートと同じ**です。

C++20 では明示的にテンプレート構文も書けます:

```cpp
auto f = []<typename T>(const std::vector<T>& v) {
    return v.size();
};
```

concept も付けられます:

```cpp
auto normalize = []<std::floating_point T>(T x, T mean, T sd) {
    return (x - mean) / sd;
};
```

## 16.7 std::function — 型を消す

ラムダはそれぞれ固有の型を持つので、**変数に入れたりコンテナに入れたりしにくい**です。

```cpp
auto f = [](int x) { return x * 2; };
f = [](int x) { return x * 3; };     // ✗ エラー: 型が違う
```

`std::function` は「呼び出せるもの」を型消去して保持します。

```cpp
#include <functional>

std::function<int(int)> f = [](int x) { return x * 2; };
f = [](int x) { return x * 3; };                    // ✓ OK
f = [](int x) { return x + 100; };                  // ✓ OK

std::vector<std::function<double(const Molecule&)>> filters;
filters.push_back([](const Molecule& m) { return m.mw; });
filters.push_back([](const Molecule& m) { return m.logp; });
```

`std::function<戻り値型(引数型...)>` という書き方です。

### ⚠️ std::function のコスト

| 項目 | 生のラムダ | `std::function` |
|---|---|---|
| サイズ | キャプチャの分だけ | **32バイト**（libstdc++） |
| ヒープ確保 | なし | **キャプチャが大きいと発生** |
| 呼び出し | **インライン展開される** | **仮想呼び出し相当。インライン不可** |
| 速度 | 最速 | 数倍遅い |

```cpp
// ✗ ホットループで std::function を呼ぶ
std::function<double(double,double)> f = [](double a, double b){ return a*b; };
for (std::size_t i = 0; i < 100'000'000; ++i) sum += f(a[i], b[i]);   // 遅い

// ✓ テンプレートで受ける（インライン展開される）
template <typename F>
double reduce(const std::vector<double>& a, const std::vector<double>& b, F f) {
    double sum = 0;
    for (std::size_t i = 0; i < a.size(); ++i) sum += f(a[i], b[i]);
    return sum;
}
```

> 💡 **使い分け:**
> - **関数の引数**として受け取る → **テンプレート `template <typename F>`**（速い）
> - **メンバ変数に保存**する、コンテナに入れる → `std::function`（柔軟）
> - コールバック、イベントハンドラ → `std::function`
> - ホットループ → **絶対にテンプレート**
>
> C++23 の `std::function_ref`（非所有の軽量版）や、
> `std::move_only_function` も選択肢です。

## 16.8 標準の関数オブジェクト

```cpp
#include <functional>

std::less<>{}          // a < b
std::greater<>{}       // a > b
std::plus<>{}          // a + b
std::minus<>{}
std::multiplies<>{}
std::divides<>{}
std::negate<>{}
std::equal_to<>{}
std::logical_and<>{}

std::sort(v.begin(), v.end(), std::greater<>{});           // 降順ソート
std::accumulate(v.begin(), v.end(), 1.0, std::multiplies<>{});
```

`<>` を空にすると型が推論されます（C++14 の透過的関数オブジェクト）。

## 16.9 🧪 実践: 柔軟なスクリーニングパイプライン

```cpp
// code/ch16/pipeline.cpp
#include <algorithm>
#include <functional>
#include <iostream>
#include <string>
#include <vector>

struct Compound {
    std::string id;
    double mw, logp, tpsa;
    int    hbd, hba, rotb;
};

// ---- フィルタを表す型 ----
using Filter = std::function<bool(const Compound&)>;

// ---- フィルタを作るファクトリ（クロージャを返す）----
Filter mw_range(double lo, double hi) {
    return [lo, hi](const Compound& c) { return c.mw >= lo && c.mw <= hi; };
}
Filter logp_max(double v) {
    return [v](const Compound& c) { return c.logp <= v; };
}
Filter tpsa_range(double lo, double hi) {
    return [lo, hi](const Compound& c) { return c.tpsa >= lo && c.tpsa <= hi; };
}
Filter rotatable_max(int n) {
    return [n](const Compound& c) { return c.rotb <= n; };
}

// ---- フィルタの合成 ----
Filter all_of_filters(std::vector<Filter> fs) {
    return [fs = std::move(fs)](const Compound& c) {
        return std::all_of(fs.begin(), fs.end(),
                           [&c](const Filter& f) { return f(c); });
    };
}
Filter any_of_filters(std::vector<Filter> fs) {
    return [fs = std::move(fs)](const Compound& c) {
        return std::any_of(fs.begin(), fs.end(),
                           [&c](const Filter& f) { return f(c); });
    };
}
Filter negate_filter(Filter f) {
    return [f = std::move(f)](const Compound& c) { return !f(c); };
}

// ---- パイプライン ----
class ScreeningPipeline {
    std::vector<std::pair<std::string, Filter>> stages_;
public:
    ScreeningPipeline& add(std::string name, Filter f) {
        stages_.emplace_back(std::move(name), std::move(f));
        return *this;                                       // メソッドチェーン
    }

    std::vector<Compound> run(const std::vector<Compound>& input) const {
        std::vector<Compound> current = input;
        std::cout << "input: " << current.size() << " compounds\n";

        for (const auto& [name, filter] : stages_) {
            std::vector<Compound> next;
            next.reserve(current.size());
            std::copy_if(current.begin(), current.end(),
                         std::back_inserter(next), filter);
            std::cout << "  after " << name << ": "
                      << next.size() << " (removed "
                      << current.size() - next.size() << ")\n";
            current = std::move(next);
        }
        return current;
    }
};

int main() {
    std::vector<Compound> library = {
        {"CMP001", 180.16, 1.19, 63.6, 1, 3, 3},
        {"CMP002", 194.19, -1.03, 61.8, 0, 6, 0},
        {"CMP003", 206.28, 3.97, 37.3, 1, 2, 4},
        {"CMP004", 151.16, 0.46, 49.3, 2, 2, 1},
        {"CMP005", 312.53, 8.23, 37.3, 1, 2, 17},
        {"CMP006",  46.07, -0.31, 20.2, 1, 1, 0},
        {"CMP007", 178.23, 4.45,  0.0, 0, 0, 0},
        {"CMP008", 165.19, -1.52, 63.3, 2, 3, 3},
        {"CMP009", 425.90, 4.10, 85.2, 2, 5, 6},
        {"CMP010", 550.60, 2.30,120.0, 4, 8, 9},
    };

    ScreeningPipeline pipeline;
    pipeline.add("MW 150-500",   mw_range(150.0, 500.0))
            .add("logP <= 5",    logp_max(5.0))
            .add("TPSA 20-140",  tpsa_range(20.0, 140.0))
            .add("RotB <= 10",   rotatable_max(10));

    auto hits = pipeline.run(library);

    std::cout << "\nsurvivors:\n";
    for (const auto& c : hits) {
        std::cout << "  " << c.id << "  MW=" << c.mw
                  << "  logP=" << c.logp << "\n";
    }

    // ---- 論理演算の合成 ----
    auto lead_like = all_of_filters({ mw_range(200.0, 350.0), logp_max(3.0) });
    auto not_lead  = negate_filter(lead_like);

    std::cout << "\nnon-lead-like: ";
    for (const auto& c : library) if (not_lead(c)) std::cout << c.id << " ";
    std::cout << "\n";
    return 0;
}
```

**設計のポイント:**

- `Filter` を `std::function` にすることで、**実行時にパイプラインを組み立てられる**
- ファクトリ関数がクロージャ（キャプチャ付きラムダ）を返す
  → 「MW 150-500」という**設定値を持った関数**が作れる
- `all_of_filters` で合成 → 複雑な条件も宣言的に書ける
- メソッドチェーン（`return *this`）で読みやすいAPI

> 💡 ここでは `std::function` のコストは問題になりません
> （1化合物あたり数回の呼び出しなので）。
> 1億回のループ内なら、テンプレート版に書き換えてください。

## 16.10 関数ポインタ（読めれば十分）

```cpp
double (*f)(double, double) = &compute;    // 関数ポインタ
f(1.0, 2.0);

using BinaryOp = double(*)(double, double);   // 型エイリアス（読みやすい）
BinaryOp g = &compute;
```

**キャプチャのないラムダは、関数ポインタに変換できます:**

```cpp
double (*p)(double) = [](double x) { return x * 2; };   // ✓ OK（キャプチャなし）
// double (*q)(double) = [n](double x) { return x * n; }; // ✗ キャプチャありは不可
```

🧪 これは **C言語のAPIにコールバックを渡すとき**に必要になります
（RDKit の C API、GLFW、OpenMP など）。

```cpp
// C の qsort にコールバックを渡す例
std::qsort(arr, n, sizeof(double), [](const void* a, const void* b) {
    double x = *static_cast<const double*>(a);
    double y = *static_cast<const double*>(b);
    return (x < y) ? -1 : (x > y) ? 1 : 0;
});
```

> 💡 ただし、C++コードでは `std::sort` を使ってください。速いです。

## 16.11 この章のまとめ

- ラムダの構文: `[キャプチャ](引数) -> 戻り値型 { 本体 }`
- **キャプチャがPythonにない最大の違い**。コピー `[x]` か参照 `[&x]` を明示する
- **保存するラムダは必ずコピーキャプチャ**（ダングリング防止）
- **ラムダの正体は、コンパイラが生成するクラス**
  → `operator()` がインライン展開されるので**速い**
- ラムダはそれぞれ**固有の型**を持つ
- `std::function` は型消去。柔軟だが**インライン展開されず遅い**
- **関数を引数に取るならテンプレート `template <typename F>`**（ホットループでは必須）
- `mutable` でコピーキャプチャした変数を変更できる
- キャプチャなしラムダは関数ポインタに変換できる（C API連携）

### 使い分け早見表

| 場面 | 書き方 |
|---|---|
| `std::sort` の比較 | `[](const T& a, const T& b){ return ...; }` |
| 関数の引数（速度重視） | `template <typename F> void f(F callback)` |
| メンバに保存 | `std::function<R(Args...)>` |
| C API のコールバック | キャプチャなしラムダ → 関数ポインタ |
| 設定値を持つ関数を作る | ファクトリ関数がクロージャを返す |
