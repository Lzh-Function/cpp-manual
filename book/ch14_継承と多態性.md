# 第14章 継承と多態性

Pythonのクラス継承は知っているはずです。C++では**仕組みが違う**ので、
そこを中心に説明します。そして最後に「なぜ最近は継承を避けるのか」も話します。

## 14.1 基本の継承

```cpp
class Descriptor {
public:
    virtual ~Descriptor() = default;                       // ★ 仮想デストラクタ
    virtual double compute(const Molecule& m) const = 0;   // ★ 純粋仮想関数
    virtual std::string name() const = 0;
};

class MolecularWeight : public Descriptor {
public:
    double compute(const Molecule& m) const override { return m.mw; }
    std::string name() const override { return "MW"; }
};
```

```python
from abc import ABC, abstractmethod

class Descriptor(ABC):
    @abstractmethod
    def compute(self, m): ...

class MolecularWeight(Descriptor):
    def compute(self, m): return m.mw
```

## 14.2 ★重要★ virtual がないと多態性が働かない

**これがPythonとの最大の違いです。**

```cpp
class Base {
public:
    void greet() { std::cout << "Base\n"; }           // ★ virtual なし
};
class Derived : public Base {
public:
    void greet() { std::cout << "Derived\n"; }
};

Derived d;
Base& b = d;
b.greet();       // ★ "Base" と出る！ Python なら "Derived"
```

```cpp
class Base {
public:
    virtual void greet() { std::cout << "Base\n"; }   // ★ virtual あり
};
class Derived : public Base {
public:
    void greet() override { std::cout << "Derived\n"; }
};

Derived d;
Base& b = d;
b.greet();       // ✓ "Derived" と出る
```

> 🐍 **Pythonでは全メソッドが暗黙的に virtual です。**
> C++では**明示的に `virtual` を書いたメソッドだけ**が動的ディスパッチされます。
>
> なぜか? **ゼロオーバーヘッド原則**です。
> virtual にはコストがあるので、必要なときだけ払わせるのです。

### virtual のコスト: vtable

```cpp
class Descriptor {
    virtual double compute(const Molecule&) const = 0;
    virtual std::string name() const = 0;
};
```

virtual 関数を持つクラスのオブジェクトには、
**隠れたポインタ（vptr）**が1個追加されます。

```
   MolecularWeight オブジェクト
   +------------------+
   | vptr ------------|----> MolecularWeight の vtable
   | (メンバ変数...)    |      +---------------------------+
   +------------------+      | ~MolecularWeight のアドレス |
                             | compute のアドレス          |
                             | name のアドレス             |
                             +---------------------------+
```

`d->compute(m)` を呼ぶと:
1. `d` から vptr を読む（メモリアクセス）
2. vtable から `compute` のアドレスを読む（メモリアクセス）
3. そのアドレスにジャンプ（**インライン展開できない**）

**コスト:**
- オブジェクトが8バイト大きくなる
- 呼び出しごとに2回の間接参照
- **インライン展開されない**（これが一番痛い）
- 分岐予測が外れる可能性

```cpp
std::cout << sizeof(struct { int x; }) << "\n";                    // 4
std::cout << sizeof(struct V { int x; virtual ~V(){} }) << "\n";   // 16 (vptr + パディング)
```

> ⚠️ **ホットループの中で virtual 呼び出しをしないでください。**
> 1億回呼ぶと、インライン展開できないだけで数倍遅くなります。
>
> 🧪 記述子計算のように「1分子あたり1回」なら全く問題ありません。
> 「原子ペアごとに1回」なら要注意です。

### override キーワード

```cpp
class Derived : public Base {
public:
    void greet() override { }        // ★ 必ず書く
};
```

`override` を書くと、**基底クラスに同じシグネチャの virtual 関数が
無ければコンパイルエラー**になります。

```cpp
class Base {
    virtual void compute(const Molecule& m) const;
};
class Derived : public Base {
    void compute(Molecule& m) const override;   // ★ const 忘れ → コンパイルエラー
    // override が無ければ「新しい関数」として静かに追加され、
    // 多態性が働かないバグになる
};
```

> 💡 **`override` は必ず書いてください。** タイポや const 忘れを防ぎます。
> これはC++11で入った、最も費用対効果の高い機能のひとつです。

### final

```cpp
class MolecularWeight final : public Descriptor {   // これ以上継承させない
    double compute(const Molecule& m) const final;  // これ以上オーバーライドさせない
};
```

`final` を付けると、コンパイラが「これ以上派生はない」と知るので、
**仮想呼び出しを直接呼び出しに最適化（devirtualization）できることがあります**。

## 14.3 ★★★ 仮想デストラクタ ★★★

**これを忘れるとメモリリークします。必ず書いてください。**

```cpp
class Base {
public:
    ~Base() { }                    // ★ virtual がない
};
class Derived : public Base {
    std::vector<double> data_;     // 大量のデータ
public:
    ~Derived() { std::cout << "Derived destroyed\n"; }
};

std::unique_ptr<Base> p = std::make_unique<Derived>();
// p が破棄されるとき... ★ ~Base() だけが呼ばれ、~Derived() は呼ばれない
// → data_ がリークする。しかも規格上は未定義動作
```

```cpp
class Base {
public:
    virtual ~Base() = default;     // ✓ これを書く
};
```

> **ルール: 継承されうるクラス（virtual 関数を持つクラス）には、
> 必ず `virtual ~Base() = default;` を書く。**

逆に、継承させないクラスには virtual デストラクタは不要です（8バイト無駄になるので）。

## 14.4 抽象クラスとインタフェース

```cpp
class Descriptor {
public:
    virtual ~Descriptor() = default;
    virtual double compute(const Molecule&) const = 0;   // ★ = 0 が純粋仮想
    virtual std::string name() const = 0;

    // 非仮想のヘルパも書ける（テンプレートメソッドパターン）
    void print(const Molecule& m) const {
        std::cout << name() << " = " << compute(m) << "\n";
    }
};
```

`= 0` を付けた関数を**純粋仮想関数**と呼び、
1つでもあるクラスは**抽象クラス**になり、インスタンス化できません。

```cpp
Descriptor d;                              // ✗ コンパイルエラー
std::unique_ptr<Descriptor> p =
    std::make_unique<MolecularWeight>();   // ✓ 派生クラスなら OK
```

Pythonの `ABC` + `@abstractmethod` と同じです。

### インタフェースの慣習

```cpp
// 純粋仮想関数だけを持つクラス = インタフェース
class Serializable {
public:
    virtual ~Serializable() = default;
    virtual std::string to_json() const = 0;
    virtual void from_json(const std::string&) = 0;
};
```

Javaの `interface` に相当します。C++には専用構文がないので、慣習で表現します。

## 14.5 多重継承（と、その罠）

C++は**多重継承を許します**（Java や C# は許しません）。

```cpp
class Serializable { public: virtual std::string to_json() const = 0; };
class Printable    { public: virtual void print() const = 0; };

class Molecule : public Serializable, public Printable {
    std::string to_json() const override { ... }
    void print() const override { ... }
};
```

**インタフェースの多重継承は安全**です。実装を持つクラスの多重継承は危険です。

### ダイヤモンド継承問題

```cpp
class A { public: int x; };
class B : public A { };
class C : public A { };
class D : public B, public C { };   // ★ D は A を2つ持つ！

D d;
d.x = 1;        // ✗ 曖昧エラー: B::A::x か C::A::x か?
d.B::x = 1;     // 明示すれば通る
```

解決策は**仮想継承**:

```cpp
class B : public virtual A { };
class C : public virtual A { };
class D : public B, public C { };   // A は1つだけ

D d;
d.x = 1;        // ✓ OK
```

> ⚠️ **仮想継承は複雑で、実行時オーバーヘッドもあります。**
> **実務では避けてください。** 多重継承は「純粋なインタフェース（データを持たない
> 抽象クラス）」に限定するのが安全です。

## 14.6 ⚠️ スライシング

**C++特有の、非常に厄介な罠です。**

```cpp
class Descriptor { virtual double compute() const; };
class LogP : public Descriptor {
    double coefficient_;
    double compute() const override;
};

LogP lp;
Descriptor d = lp;      // ★ スライシング！ 派生部分が切り落とされる
d.compute();            // ★ Descriptor::compute が呼ばれる
```

```
   LogP オブジェクト             Descriptor 変数（サイズが小さい）
   +------------------+          +------------------+
   | vptr             |   ───>   | vptr (Descriptor)|
   | Descriptor 部分   |          +------------------+
   | coefficient_     |          ★ coefficient_ は入りきらない → 消える
   +------------------+
```

**値で受けると、派生クラスの情報が失われます。**

```cpp
void f(Descriptor d);          // ✗ スライシングが起きる
void g(const Descriptor& d);   // ✓ 参照なら OK
void h(Descriptor* d);         // ✓ ポインタなら OK
```

> ⚠️ **さらに危険な例:**
> ```cpp
> std::vector<Descriptor> v;      // ✗ 派生クラスを入れるとスライシング
> v.push_back(LogP{});            //   LogP の部分が消える
>
> std::vector<std::unique_ptr<Descriptor>> v;   // ✓ 正しい
> v.push_back(std::make_unique<LogP>());
> ```
>
> **「多態的なコンテナは必ずスマートポインタで持つ」**と覚えてください。

対策として、基底クラスのコピーを禁止する手もあります:

```cpp
class Descriptor {
public:
    virtual ~Descriptor() = default;
protected:
    Descriptor() = default;
    Descriptor(const Descriptor&) = default;      // 派生からは使えるが
    Descriptor& operator=(const Descriptor&) = default;
    // public でないので、外部からのスライシングを防げる
};
```

## 14.7 dynamic_cast — 実行時の型判定

```cpp
std::unique_ptr<Descriptor> d = make_descriptor("LogP");

if (auto* lp = dynamic_cast<LogP*>(d.get())) {
    // LogP だった場合の処理
    lp->set_coefficient(1.5);
}
```

```python
if isinstance(d, LogP):
    d.set_coefficient(1.5)
```

`dynamic_cast` は失敗すると `nullptr` を返します（参照版は例外を投げます）。

> ⚠️ **`dynamic_cast` は遅い**です（型情報を実行時に辿る）。
> そして、**使いたくなったら設計を疑ってください。**
>
> 「基底クラスのポインタを持っているのに、実際の型を知りたい」というのは、
> **仮想関数として設計すべきだった**サインです。
>
> ```cpp
> // ✗ 悪い設計
> if (dynamic_cast<AromaticRing*>(r)) { ... }
> else if (dynamic_cast<AliphaticRing*>(r)) { ... }
>
> // ✓ 良い設計
> r->process();     // 仮想関数で分岐させる
> ```

`typeid` もあります:

```cpp
#include <typeinfo>
std::cout << typeid(*d).name() << "\n";   // 型名（マングリングされている）
```

> 💡 RTTI（実行時型情報）は `-fno-rtti` で無効化できます。
> 一部のプロジェクト（LLVM など）はこれを無効にして、
> 独自の軽量な型判定機構を使っています。

## 14.8 ★継承より合成★

現代C++（というかモダンなOOP全般）の主流な考え方です。

> **「is-a」の関係でなければ、継承してはいけない。**
> **多くの場合、継承より合成 (composition) の方が良い。**

```cpp
// ✗ 継承の乱用
class MoleculeWithCache : public Molecule {
    mutable std::unordered_map<std::string, double> cache_;
};

// ✓ 合成
class CachedDescriptorCalculator {
    Molecule mol_;                                            // 持つ
    mutable std::unordered_map<std::string, double> cache_;
public:
    double get(const std::string& name) const;
};
```

継承を使うべきなのは:
- **本当に「is-a」の関係**（LogP is a Descriptor ✓）
- **多態性が必要**（異なる実装を同じインタフェースで扱いたい）

それ以外は合成を検討してください。

### 継承の代わりになる選択肢

| やりたいこと | 継承の代わりに |
|---|---|
| 実行時に振る舞いを変える | **`std::function`**（第16章）、**`std::variant`**（第17章） |
| コンパイル時に振る舞いを変える | **テンプレート**（第15章）、CRTP |
| 共通のコードを再利用したい | **自由関数** + 合成 |
| 型を統一して扱いたい | `std::variant` + `std::visit` |

### std::variant による代替（型安全な union）

```cpp
#include <variant>

struct MolecularWeight { double compute(const Molecule& m) const { return m.mw; } };
struct LogP            { double compute(const Molecule& m) const { return m.logp; } };
struct TPSA            { double compute(const Molecule& m) const { return m.tpsa; } };

using AnyDescriptor = std::variant<MolecularWeight, LogP, TPSA>;

double compute(const AnyDescriptor& d, const Molecule& m) {
    return std::visit([&m](const auto& desc){ return desc.compute(m); }, d);
}

std::vector<AnyDescriptor> descriptors = { MolecularWeight{}, LogP{}, TPSA{} };
for (const auto& d : descriptors) {
    std::cout << compute(d, mol) << "\n";
}
```

**メリット:**
- **ヒープ確保が不要**（vector の中に値として置ける）
- **仮想呼び出しがない**（`std::visit` はジャンプテーブル、インライン展開されうる）
- キャッシュ効率が良い

**デメリット:**
- **型の一覧をコンパイル時に固定する必要がある**（プラグイン的な拡張ができない）
- コンパイル時間が増える

> 🧪 **使い分け:**
> - 種類が固定（原子の種類、結合の種類、トークンの種類） → **`variant`**
> - 実行時に増える（ユーザー定義の記述子、プラグイン） → **継承 + `unique_ptr`**

## 14.9 CRTP（読めれば十分）

「不思議に再帰したテンプレートパターン」— 仮想関数のコストなしに
静的な多態性を実現する技法です。

```cpp
template <typename Derived>
class DescriptorBase {
public:
    double compute(const Molecule& m) const {
        return static_cast<const Derived*>(this)->compute_impl(m);
    }
    void print(const Molecule& m) const {
        std::cout << static_cast<const Derived*>(this)->name_impl()
                  << " = " << compute(m) << "\n";
    }
};

class MolecularWeight : public DescriptorBase<MolecularWeight> {
    friend class DescriptorBase<MolecularWeight>;
    double compute_impl(const Molecule& m) const { return m.mw; }
    std::string name_impl() const { return "MW"; }
};
```

**virtual なしで、基底クラスから派生クラスの実装を呼べます。**
すべてコンパイル時に解決されるので、インライン展開されます。

> 💡 Eigen（線形代数ライブラリ）や RDKit の一部で使われています。
> **書く必要はほぼありませんが、読めると役に立ちます。**
> C++20 の concept（第15章）があれば、より読みやすく同じことができます。

## 14.10 🧪 実践: SMILESのAST（variant版と継承版）

分子式のパース結果を表現する例で、両方のアプローチを比較します。

### 継承版

```cpp
// code/ch14/ast_inherit.cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class SmilesNode {
public:
    virtual ~SmilesNode() = default;
    virtual std::string describe() const = 0;
    virtual int atom_count() const = 0;
};

class AtomNode : public SmilesNode {
    std::string symbol_;
public:
    explicit AtomNode(std::string s) : symbol_(std::move(s)) {}
    std::string describe() const override { return "Atom(" + symbol_ + ")"; }
    int atom_count() const override { return 1; }
};

class BranchNode : public SmilesNode {
    std::vector<std::unique_ptr<SmilesNode>> children_;
public:
    void add(std::unique_ptr<SmilesNode> n) { children_.push_back(std::move(n)); }
    std::string describe() const override {
        std::string s = "Branch(";
        for (const auto& c : children_) s += c->describe() + " ";
        return s + ")";
    }
    int atom_count() const override {
        int n = 0;
        for (const auto& c : children_) n += c->atom_count();
        return n;
    }
};

int main() {
    auto branch = std::make_unique<BranchNode>();
    branch->add(std::make_unique<AtomNode>("C"));
    branch->add(std::make_unique<AtomNode>("O"));

    std::cout << branch->describe() << "\n";
    std::cout << "atoms: " << branch->atom_count() << "\n";
}
```

### variant 版

```cpp
// code/ch14/ast_variant.cpp
#include <iostream>
#include <memory>
#include <string>
#include <variant>
#include <vector>

struct AtomNode;
struct BranchNode;
using SmilesNode = std::variant<AtomNode, BranchNode>;

struct AtomNode {
    std::string symbol;
};

struct BranchNode {
    // 再帰的なので、ここだけはポインタが必要（サイズが確定しないため）
    std::vector<std::unique_ptr<SmilesNode>> children;
};

std::string describe(const SmilesNode& n);

int atom_count(const SmilesNode& n) {
    return std::visit([](const auto& node) -> int {
        using T = std::decay_t<decltype(node)>;
        if constexpr (std::is_same_v<T, AtomNode>) {
            return 1;
        } else {
            int total = 0;
            for (const auto& c : node.children) total += atom_count(*c);
            return total;
        }
    }, n);
}

std::string describe(const SmilesNode& n) {
    return std::visit([](const auto& node) -> std::string {
        using T = std::decay_t<decltype(node)>;
        if constexpr (std::is_same_v<T, AtomNode>) {
            return "Atom(" + node.symbol + ")";
        } else {
            std::string s = "Branch(";
            for (const auto& c : node.children) s += describe(*c) + " ";
            return s + ")";
        }
    }, n);
}

int main() {
    BranchNode b;
    b.children.push_back(std::make_unique<SmilesNode>(AtomNode{"C"}));
    b.children.push_back(std::make_unique<SmilesNode>(AtomNode{"O"}));

    SmilesNode root = std::move(b);
    std::cout << describe(root) << "\n";
    std::cout << "atoms: " << atom_count(root) << "\n";
}
```

> 💡 この例では継承版の方が読みやすいですね。
> `variant` が輝くのは、**再帰しない、種類が少ない、値として持ちたい**場合です。
> 例: トークンの種類、原子の型、結合次数。
>
> **道具は使い分けるものです。** 継承が悪なのではなく、
> 「すべてを継承で解決しようとする」のが問題なのです。

## 14.11 この章のまとめ

- **`virtual` を書かないと多態性が働かない**（Pythonと最大の違い）
- **`override` は必ず書く**（タイポとシグネチャ違いを防ぐ）
- **基底クラスには `virtual ~Base() = default;` を必ず書く**
- virtual にはコストがある（vptr 8バイト、間接呼び出し、インライン不可）
- 抽象クラス = 純粋仮想関数 `= 0` を持つクラス
- **スライシングに注意**。多態的なものは必ず参照・ポインタ・スマートポインタで扱う
- 多重継承は「純粋なインタフェース」に限定する
- `dynamic_cast` を使いたくなったら設計を疑う
- **継承より合成。種類が固定なら `std::variant` も検討**
