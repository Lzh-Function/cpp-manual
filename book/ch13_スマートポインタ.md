# 第13章 スマートポインタと所有権設計

「C++はメモリリークする」「セグフォる」——この評判の9割を消してくれるのが、
スマートポインタです。

## 13.1 所有権という考え方

C++でメモリ管理を考えるとき、いつも問うべきなのは:

> **このオブジェクトを解放する責任は、誰にあるのか?**

これが「**所有権 (ownership)**」です。

```cpp
Molecule* m = new Molecule("CCO");
process(m);
// ★ ここで delete すべき? それとも process が delete した?
```

生ポインタは、この問いに答えられません。関数のシグネチャを見ても、
所有権を渡しているのか、単に見せているだけなのか分かりません。

**スマートポインタは、所有権を型で表現します。**

| 型 | 所有権 | 意味 |
|---|---|---|
| `std::unique_ptr<T>` | **単独所有** | 「私だけが持つ。私が死んだら解放する」 |
| `std::shared_ptr<T>` | **共有所有** | 「みんなで持つ。最後の1人が解放する」 |
| `std::weak_ptr<T>` | 所有しない観測 | 「見てるだけ。消えたら分かる」 |
| `T*`（生ポインタ） | **所有しない** | 「借りているだけ。解放はしない」 |
| `T&`（参照） | **所有しない** | 「借りているだけ。nullにならない」 |

> 🐍 **Pythonとの対比**
>
> Pythonは全部 `shared_ptr` のようなもの（参照カウント）+ GC です。
> 「誰が解放するか」を考える必要がありません。
>
> C++は明示的に決める必要がありますが、その代わり:
> - **決定的なタイミングで解放される**（GCの一時停止がない）
> - 参照カウントの更新コストがない（`unique_ptr` なら）
> - リソース（ファイル、ロック）も同じ仕組みで管理できる

## 13.2 std::unique_ptr — 最も使うスマートポインタ

```cpp
#include <memory>

// 生成
auto mol = std::make_unique<Molecule>("CCO");

// 使う（生ポインタと同じ書き方）
std::cout << mol->num_atoms() << "\n";
std::cout << (*mol).num_atoms() << "\n";

// スコープを抜けると自動的に delete される
```

**`new` も `delete` も書きません。**

### なぜ `make_unique` を使うのか

```cpp
std::unique_ptr<Molecule> a(new Molecule("CCO"));   // 動くが非推奨
auto b = std::make_unique<Molecule>("CCO");         // ✓ 推奨
```

理由:
1. `new` を書かなくて済む（見た目が統一される）
2. 型名を2回書かなくて済む
3. **例外安全**（C++14以前、`f(new A, new B)` で片方だけリークする問題があった）
4. 1回のメモリ確保で済む場合がある（`make_shared` の場合）

### コピーできない、ムーブできる

```cpp
auto a = std::make_unique<Molecule>("CCO");
auto b = a;              // ✗ コンパイルエラー（単独所有だからコピーできない）
auto c = std::move(a);   // ✓ 所有権の移動。a は nullptr になる

if (!a) std::cout << "a is now empty\n";
```

**「単独所有」が型で強制されています。** これがコンパイル時の安全性です。

### 関数との受け渡し

```cpp
// ① 所有権を渡す（引数を値で受け取る）
void take_ownership(std::unique_ptr<Molecule> m) {
    // m はこの関数のもの。関数を抜けたら解放される
}
take_ownership(std::move(mol));   // ★ std::move が必須

// ② 所有権は渡さず、使うだけ（参照 or 生ポインタで受ける）
void use(const Molecule& m);       // ★ 推奨: null にならないと保証できる
void use2(const Molecule* m);      // null かもしれない場合

use(*mol);
use2(mol.get());                   // .get() で生ポインタを取り出す

// ③ 所有権を返す
std::unique_ptr<Molecule> create(std::string smiles) {
    return std::make_unique<Molecule>(std::move(smiles));
}
```

> 💡 **関数のシグネチャが所有権を語る**
>
> ```cpp
> void f(std::unique_ptr<T> p);     // 「所有権をください」
> void g(const T& t);               // 「見せてください（必ずある）」
> void h(T* t);                     // 「見せてください（nullかも）」
> std::unique_ptr<T> make();        // 「所有権をあげます」
> ```
>
> これが読めるようになると、他人のC++コードが一気に理解しやすくなります。

### unique_ptr の操作

```cpp
auto p = std::make_unique<Molecule>("CCO");

p.get();          // 生ポインタを取得（所有権は移らない）
p.reset();        // 解放して nullptr にする
p.reset(new Molecule("CCC"));   // 古いのを解放して新しいのを持つ
auto raw = p.release();         // 所有権を放棄して生ポインタを返す（要手動delete）
if (p) { }        // null チェック
p.swap(q);
```

### 配列版

```cpp
auto arr = std::make_unique<double[]>(1000);   // double[1000]
arr[0] = 1.0;
// 自動的に delete[] される
```

> ⚠️ ただし、**ほとんどの場合 `std::vector<double>` の方が良い**です。
> サイズを覚えていて、リサイズもでき、イテレータも使えます。
> `unique_ptr<T[]>` を使うのは、サイズが固定で、かつ
> vector の24バイトのオーバーヘッドすら惜しい場合だけです。

### カスタムデリータ — C言語ライブラリとの連携

```cpp
// Cのライブラリが返すポインタを RAII で管理する
struct FileCloser {
    void operator()(std::FILE* f) const { if (f) std::fclose(f); }
};
using FilePtr = std::unique_ptr<std::FILE, FileCloser>;

FilePtr fp(std::fopen("data.sdf", "r"));
// スコープを抜けると自動的に fclose される
```

🧪 **RDKit の C API や、Open Babel、xtb などのCライブラリを
使うときに非常に有用**です。

ラムダでも書けます:

```cpp
auto deleter = [](std::FILE* f) { if (f) std::fclose(f); };
std::unique_ptr<std::FILE, decltype(deleter)> fp(std::fopen("x", "r"), deleter);
```

### オーバーヘッドはゼロ

```cpp
sizeof(std::unique_ptr<Molecule>)   // 8 （生ポインタと同じ！）
```

**`unique_ptr` は生ポインタと全く同じサイズ・同じ速度**です。
デリータがステートレスなら、追加のメモリもゼロ。
`->` や `*` もインライン展開されて、生ポインタと同じ機械語になります。

これがゼロオーバーヘッド原則です。**安全なのにタダ。**

## 13.3 std::shared_ptr — 共有所有

```cpp
auto a = std::make_shared<Molecule>("CCO");
auto b = a;                    // ✓ コピーできる。参照カウントが2になる

std::cout << a.use_count();    // 2

// a も b もスコープを抜けたとき、初めて解放される
```

```
   a ──┐
       ├──> [制御ブロック: refcount=2, weakcount=0] ──> [Molecule データ]
   b ──┘
```

`shared_ptr` は**参照カウント**を持ちます。Pythonのオブジェクトと同じ仕組みです。

### コスト

| 項目 | `unique_ptr` | `shared_ptr` |
|---|---|---|
| サイズ | 8バイト | **16バイト**（ポインタ + 制御ブロックへのポインタ） |
| コピー | 不可 | **可能だが、アトミックな参照カウント更新が必要** |
| メモリ確保 | 1回 | `make_shared` なら1回、そうでなければ2回 |
| 速度 | 生ポインタと同じ | 参照カウント更新のたびにアトミック操作 |

> ⚠️ **アトミック操作は意外と重い**です。
> マルチスレッドで `shared_ptr` をコピーしまくると、
> キャッシュラインの奪い合い（false sharing）で著しく遅くなります。
>
> ```cpp
> void f(std::shared_ptr<Molecule> m);        // ✗ 呼ぶたびに参照カウント更新
> void g(const std::shared_ptr<Molecule>& m); // △ ましだが、なぜ shared が必要?
> void h(const Molecule& m);                  // ✓ 最速。所有権が不要なら常にこれ
> ```

### いつ shared_ptr を使うか

> **原則: まず `unique_ptr` を試す。本当に共有が必要なときだけ `shared_ptr`。**

正当な用途:
- **キャッシュ**: 同じ分子オブジェクトを複数の場所から参照する
- **グラフ/DAG**: ノードが複数の親から参照される
- **非同期処理**: どのスレッドが最後まで使うか分からない
- **観測者パターン**: リスナーの寿命が不定

```cpp
// 🧪 分子のキャッシュ（同じSMILESなら同じオブジェクトを共有）
class MoleculeCache {
    std::unordered_map<std::string, std::shared_ptr<const Molecule>> cache_;
public:
    std::shared_ptr<const Molecule> get(const std::string& smiles) {
        auto it = cache_.find(smiles);
        if (it != cache_.end()) return it->second;

        auto mol = std::make_shared<const Molecule>(parse_smiles(smiles));
        cache_.emplace(smiles, mol);
        return mol;
    }
};
```

> 💡 `shared_ptr<const T>` にすると、共有しているオブジェクトを
> 誰も変更できなくなります。**共有 + 不変 = スレッドセーフ**。
> 良い設計パターンです。

### make_shared vs shared_ptr(new T)

```cpp
auto a = std::make_shared<Molecule>("CCO");         // ✓ メモリ確保1回
std::shared_ptr<Molecule> b(new Molecule("CCO"));   // ✗ メモリ確保2回
```

`make_shared` は制御ブロックとオブジェクトを**1回の確保**でまとめます。
速く、キャッシュ効率も良いです。

> ⚠️ ただし、`weak_ptr` が生きている間は**オブジェクトのメモリも解放されません**
> （制御ブロックと一体だから）。巨大なオブジェクトで多数の `weak_ptr` を
> 使う場合は、`shared_ptr(new T)` の方が良いこともあります。レアケースです。

## 13.4 std::weak_ptr — 循環参照を断つ

### 循環参照の問題

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;      // ★ 循環！
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->prev = a;
// ★ a と b の参照カウントが互いに1以上のまま。永久に解放されない = メモリリーク
```

```
   a ──next──> b
   a <──prev── b

   a の refcount = 2 (外部 + b->prev)
   b の refcount = 2 (外部 + a->next)

   外部の参照が消えても、互いに1ずつ残る → 解放されない
```

> 🐍 **Pythonでは循環GCが自動で解決します。**
> C++には GC がないので、自分で対処する必要があります。

### weak_ptr による解決

```cpp
struct Node {
    std::shared_ptr<Node> next;      // 所有する
    std::weak_ptr<Node>   prev;      // ★ 所有しない観測
};
```

`weak_ptr` は参照カウントを増やしません。使うときは `lock()` で
一時的な `shared_ptr` に変換します:

```cpp
if (auto p = node->prev.lock()) {   // 生きていれば shared_ptr が返る
    p->do_something();
} else {
    // すでに解放されている
}
```

> 💡 **ルール: 親→子は `shared_ptr`、子→親は `weak_ptr`。**
> ツリー構造やグラフでの定石です。

🧪 **分子グラフでは、通常この問題は起きません。**
なぜなら、原子と結合を `std::vector` に持ち、**インデックスで参照する**からです
（第11章の `Molecule` クラス）。

```cpp
// ✓ 推奨: インデックスベース。循環も所有権の問題もない
class Molecule {
    std::vector<Atom> atoms_;
    std::vector<Bond> bonds_;         // Bond は原子のインデックスを持つ
    std::vector<std::vector<std::uint32_t>> adjacency_;
};
```

**グラフ構造では、ポインタよりインデックスの方が優れています:**
- 循環参照の問題がない
- メモリが連続（キャッシュ効率）
- シリアライズが簡単（そのままバイナリ保存できる）
- サイズが小さい（`uint32_t` 4バイト vs ポインタ8バイト）

これは実務での重要な設計知見です。

## 13.5 生ポインタはいつ使うか

**「所有しない、null かもしれない参照」を表すときだけ**です。

```cpp
// 見つからなければ nullptr を返す
const Molecule* find_molecule(const std::string& id) const {
    auto it = index_.find(id);
    return it == index_.end() ? nullptr : &records_[it->second];
}

if (const auto* m = find_molecule("CHEMBL25")) {
    use(*m);
}
```

現代的には `std::optional<std::reference_wrapper<T>>` や
ガイドライン・サポート・ライブラリの `gsl::not_null` もありますが、
**この用途の生ポインタは今でも正当**です。

> ⚠️ **生ポインタで `delete` は絶対にしない。**
> `new` と `delete` を書いた瞬間、あなたは Rule of Five と
> 例外安全性の責任を負うことになります。

## 13.6 所有権設計フローチャート

```
   オブジェクトをどう持つ?
        │
   動的確保が必要?（サイズが実行時に決まる、多態性が必要、寿命がスコープを超える）
        │
   ┌────┴────┐
  No         Yes
   │          │
値で持つ    複数箇所から所有される?
(スタック)      │
   │      ┌────┴────┐
   │     No         Yes
   │      │          │
   │  unique_ptr  shared_ptr
   │                 │
   │            循環する?
   │                 │
   │            ┌────┴────┐
   │           No        Yes
   │            │          │
   │          そのまま  片方を weak_ptr
   │                    （またはインデックス設計に変更）
   ▼
最も速く、最もシンプル。可能な限りこれを選ぶ
```

### 優先順位（上から順に検討する）

1. **値で持つ**（`Molecule m;`）— 最速、最も安全
2. **`std::vector<T>`** — 複数持つならこれ
3. **`std::unique_ptr<T>`** — 多態性が必要、または寿命の管理が必要
4. **`std::shared_ptr<T>`** — 本当に共有が必要なときだけ
5. **生ポインタ `T*`** — 所有しない観測のみ
6. **`new`/`delete`** — 書かない

## 13.7 🧪 実践: プラグイン形式の記述子計算器

`unique_ptr` と多態性（第14章の先取り）を組み合わせた実用パターンです。

```cpp
// code/ch13/descriptor_plugin.cpp
#include <cmath>
#include <iostream>
#include <memory>
#include <string>
#include <unordered_map>
#include <vector>

// ---- 簡易 Molecule（本来は第11章のもの）----
struct Molecule {
    std::string smiles;
    int    heavy_atoms = 0;
    int    rings       = 0;
    int    hbd         = 0;
    int    hba         = 0;
    double mw          = 0.0;
    double logp        = 0.0;
};

// ---- 記述子計算器のインタフェース ----
class Descriptor {
public:
    virtual ~Descriptor() = default;                     // ★ 仮想デストラクタ必須
    virtual std::string name()  const = 0;
    virtual double compute(const Molecule& m) const = 0;
};

// ---- 具体的な実装たち ----
class MolecularWeight : public Descriptor {
public:
    std::string name() const override { return "MW"; }
    double compute(const Molecule& m) const override { return m.mw; }
};

class LogP : public Descriptor {
public:
    std::string name() const override { return "LogP"; }
    double compute(const Molecule& m) const override { return m.logp; }
};

class LipinskiViolations : public Descriptor {
public:
    std::string name() const override { return "Ro5_violations"; }
    double compute(const Molecule& m) const override {
        int v = 0;
        if (m.mw   > 500.0) ++v;
        if (m.logp > 5.0)   ++v;
        if (m.hbd  > 5)     ++v;
        if (m.hba  > 10)    ++v;
        return v;
    }
};

class FractionCsp3 : public Descriptor {
public:
    std::string name() const override { return "FractionCSP3"; }
    double compute(const Molecule& m) const override {
        // 簡易推定（本来は原子ごとの混成を見る）
        if (m.heavy_atoms == 0) return 0.0;
        return 1.0 - static_cast<double>(m.rings * 6) / m.heavy_atoms;
    }
};

// ---- 記述子の集合を管理する ----
class DescriptorSet {
    std::vector<std::unique_ptr<Descriptor>> descriptors_;   // ★ 単独所有

public:
    void add(std::unique_ptr<Descriptor> d) {
        descriptors_.push_back(std::move(d));                // ★ ムーブが必須
    }

    std::vector<double> compute_all(const Molecule& m) const {
        std::vector<double> out;
        out.reserve(descriptors_.size());
        for (const auto& d : descriptors_) {                 // const auto& でコピー回避
            out.push_back(d->compute(m));
        }
        return out;
    }

    std::vector<std::string> names() const {
        std::vector<std::string> out;
        out.reserve(descriptors_.size());
        for (const auto& d : descriptors_) out.push_back(d->name());
        return out;
    }

    std::size_t size() const noexcept { return descriptors_.size(); }
};

// ---- ファクトリ関数（名前から生成）----
std::unique_ptr<Descriptor> make_descriptor(const std::string& name) {
    if (name == "MW")             return std::make_unique<MolecularWeight>();
    if (name == "LogP")           return std::make_unique<LogP>();
    if (name == "Ro5_violations") return std::make_unique<LipinskiViolations>();
    if (name == "FractionCSP3")   return std::make_unique<FractionCsp3>();
    return nullptr;
}

int main() {
    DescriptorSet ds;
    for (const auto& n : {"MW", "LogP", "Ro5_violations", "FractionCSP3"}) {
        if (auto d = make_descriptor(n)) ds.add(std::move(d));
    }

    std::vector<Molecule> mols = {
        {"CC(=O)Oc1ccccc1C(=O)O", 13, 1, 1, 3, 180.16, 1.19},
        {"Cn1cnc2c1c(=O)n(C)c(=O)n2C", 14, 2, 0, 6, 194.19, -1.03},
        {"CCCCCCCCCCCCCCCCCCCC(=O)O", 22, 0, 1, 2, 312.53, 8.23},
    };

    // ヘッダ
    std::cout << "SMILES                       ";
    for (const auto& n : ds.names()) std::cout << n << "  ";
    std::cout << "\n";

    for (const auto& m : mols) {
        std::cout << m.smiles;
        for (std::size_t k = m.smiles.size(); k < 29; ++k) std::cout << ' ';
        for (double v : ds.compute_all(m)) std::cout << v << "  ";
        std::cout << "\n";
    }
    return 0;
}
```

**このパターンの良いところ:**

- `DescriptorSet` が記述子の所有権を明確に持つ（`unique_ptr`）
- 新しい記述子は `Descriptor` を継承するだけで追加できる
- `DescriptorSet` のデストラクタで全部自動解放される（`delete` を書かない）
- コピーもムーブも正しく動く（`unique_ptr` がコピー不可なので、
  `DescriptorSet` も自動的にコピー不可になる = 意図通り）

## 13.8 よくある間違い

### ① 同じ生ポインタから複数の smart_ptr を作る

```cpp
Molecule* raw = new Molecule("CCO");
std::shared_ptr<Molecule> a(raw);
std::shared_ptr<Molecule> b(raw);   // ★ 別々の制御ブロックができる → 二重解放
```

**対策: `make_shared` / `make_unique` だけを使う。** 生ポインタを経由しない。

### ② unique_ptr をコピーしようとする

```cpp
void f(std::unique_ptr<Molecule> m);
auto p = std::make_unique<Molecule>("CCO");
f(p);              // ✗ コンパイルエラー
f(std::move(p));   // ✓
```

### ③ shared_ptr を値で渡しまくる

```cpp
void f(std::shared_ptr<Molecule> m);   // ✗ 呼ぶたびにアトミック操作
void g(const Molecule& m);             // ✓ 所有権が要らないなら
```

### ④ this から shared_ptr を作る

```cpp
class Bad {
    void register_self() {
        registry.push_back(std::shared_ptr<Bad>(this));   // ★ 二重解放
    }
};
```

必要なら `std::enable_shared_from_this` を使います（レアケース）。

### ⑤ 仮想デストラクタを忘れる

```cpp
class Base { public: ~Base() {} };          // ★ virtual がない
class Derived : public Base { std::vector<int> data_; };

std::unique_ptr<Base> p = std::make_unique<Derived>();
// ★ p が解放されるとき、~Derived() が呼ばれない → data_ がリーク
```

**基底クラスには必ず `virtual ~Base() = default;` を書いてください**（第14章）。

## 13.9 この章のまとめ

- **所有権を型で表現する**のがスマートポインタの本質
- **`unique_ptr` が第一選択**。生ポインタと同じサイズ・速度でゼロオーバーヘッド
- `make_unique` / `make_shared` を使う。**`new` は書かない**
- `unique_ptr` はコピー不可、ムーブ可。所有権の移動が明示的
- `shared_ptr` は参照カウント。**アトミック操作のコストがある**ので、
  本当に共有が必要なときだけ
- 循環参照には `weak_ptr`。ただし**グラフはインデックスで持つ方が良い**
- 生ポインタは「所有しない観測」専用。`delete` は書かない
- **優先順位: 値 > vector > unique_ptr > shared_ptr**

### 所有権チートシート

```cpp
Molecule  m;                                  // 値。最速。まずこれ
std::vector<Molecule> ms;                     // 複数持つ

std::unique_ptr<Molecule> p = std::make_unique<Molecule>(...);  // 単独所有
std::shared_ptr<Molecule> s = std::make_shared<Molecule>(...);  // 共有所有
std::weak_ptr<Molecule>   w = s;                                // 観測のみ

void f(const Molecule& m);            // 借りる（必ずある）
void g(Molecule* m);                  // 借りる（null かも）
void h(std::unique_ptr<Molecule> m);  // もらう
std::unique_ptr<Molecule> k();        // あげる
```
