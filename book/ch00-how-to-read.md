# 第0章 この本の読み方

## 0.1 あなたはたぶん、こういう人

- PyTorch/scikit-learn で分子物性予測モデルを組んでいる
- RDKit で `Chem.MolFromSmiles()` を毎日呼んでいる
- `for` ループで100万分子を回したら、**帰宅して寝て起きてもまだ終わっていない**
- Cython や Numba を試したが、複雑になると手に負えなくなった
- 論文の実装が C++ で、読めなくて詰んだ
- 共同研究先から「そのアルゴリズム、C++で書き直してくれない?」と言われた

このどれかに当てはまるなら、この本は役に立ちます。

## 0.2 この本が目指すゴール

読み終わったとき、あなたは以下ができるようになります。

1. **C++のコードが読める** — GitHub の C++ プロジェクトを開いても目が滑らない
2. **C++のコードが書ける** — 「アルゴリズムを1つ、C++で実装して」に応えられる
3. **なぜ速いのか説明できる** — メモリレイアウトとキャッシュの話ができる
4. **PythonとC++を橋渡しできる** — ホットスポットだけC++に落として `import` する
5. **自分でデバッグできる** — セグフォやコンパイルエラーで泣かなくなる

逆に、この本では扱わないもの:
- GUI プログラミング（Qt など）
- ゲームエンジンやグラフィックス
- 組込み・リアルタイム制約下の特殊な作法
- C++ の言語規格の隅々（規格書は1900ページあります。読まなくていいです）

## 0.3 3つの読み方

### ルートA: とにかく最短で「使える」ようになりたい（2〜3週間）

```
第1章 → 第2章 → 第3章 → 第4章 → 第5章 → 第6章(重要) → 第7章 → 第8章
     → 第9章 → 第10章 → 第11章 → 第13章 → 第17章 → 第19章 → 第26章
```

第6章（メモリモデル）だけは絶対に飛ばさないでください。ここが分かるかどうかで、
その後の理解速度が5倍変わります。

### ルートB: 実践から入りたい（コードを動かしながら学ぶ派）

```
第2章(環境構築) → 第3章 → 第20章(SMILESパーサ)を写経
  → 分からない文法が出るたびに第II部を辞書的に引く
```

第20〜24章は、第II部の文法を**実際に使っている場所**への参照リンクを張ってあります。

### ルートC: 網羅的にきっちり（1〜2ヶ月）

第0章から順番に。各章末の練習問題を解いてください。

## 0.4 この本の「噛み砕き」方針

C++の入門書がつまずかせる典型パターンと、この本での対処:

| つまずきポイント | よくある説明 | この本の説明 |
|---|---|---|
| ポインタ | 「アドレスを格納する変数」 | メモリを**方眼紙の絵**で描いて、`id()` と対比 |
| 参照 | 「別名」 | Pythonの変数代入と**同じ挙動**であることを示す |
| ムーブ | 「右辺値参照が…」 | 「引っ越しの荷物、箱ごと渡すか中身を詰め直すか」 |
| テンプレート | 「型パラメータ化」 | 「Pythonの関数は最初からテンプレート」 |
| RAII | 「資源獲得は初期化」 | 「`with` 文が言語に組み込まれたもの」 |
| const | 「定数性」 | 「型で書く単体テスト」 |
| ヘッダ/実装分離 | 「宣言と定義」 | 「`.pyi` スタブと `.py` 本体」 |

## 0.5 心構え: C++を「怖い言語」にしないために

C++には**35年分の歴史**が地層のように積もっています。
2000年代の書き方、C言語由来の書き方、モダンな書き方が全部有効です。
だから Stack Overflow で見つかるコードの半分は「もう書かない方がいい書き方」です。

**この本では、原則として C++17/20 のモダンな書き方だけを教えます。**
古い書き方は「こういうコードを見たらこう読み替えて」という形で補足します。

覚えておくべき3つのルール:

> **ルール1: `new` と `delete` は自分で書かない**
> （`std::vector` と `std::unique_ptr` を使う。第13章）

> **ルール2: 生ポインタは「所有しない参照」としてだけ使う**
> （所有権は必ずスマートポインタかコンテナが持つ。第13章）

> **ルール3: 型に嘘をつかない**
> （`void*` と `reinterpret_cast` を使いたくなったら設計を疑う。第4章）

この3つを守るだけで、C++の危険度は9割減ります。
「C++はセグフォる」「メモリリークする」の大半は、この3つを破ったコードの話です。

## 0.6 動作環境

本書のコードは以下で検証しています。

| 環境 | コンパイラ | 標準 |
|---|---|---|
| Linux (Ubuntu 22.04+) | GCC 12+ / Clang 15+ | C++20 |
| macOS 13+ | Apple Clang 14+ | C++20 |
| Windows 11 | MSVC 19.36+ (VS2022) / MinGW-w64 GCC 13+ | C++20 |

C++20 の一部機能（`std::format`, `ranges` の一部, `std::expected` は C++23）は
コンパイラによって未対応な場合があります。その都度、代替手段を併記します。

## 0.7 コードの入手

本書のサンプルコードは `book/code/` 以下にあります。

```
book/code/
├── ch03/            単一ファイル・複数ファイルのビルド
├── ch05/            SMILESの文字処理
├── ch06/            メモリレイアウトのベンチマーク
├── ch07/            reserve と capacity の観察
├── ch08/            string_view トークナイザ
├── ch11/            RAII スコープタイマー
├── ch12/            コピー/ムーブ/noexcept のベンチマーク
└── chemcpp/         ★ 第III部で作る本格的なライブラリ
    ├── CMakeLists.txt / CMakePresets.json
    ├── include/chemcpp/   element, molecule, smiles, graph,
    │                      fingerprint, similarity, database,
    │                      search, descriptors, io
    ├── src/               各実装
    ├── apps/              parse_demo, fp_demo, screen, descriptors_cli
    ├── tests/             Catch2 テストスイート
    └── data/sample.smi    サンプルデータ
```

`chemcpp/` は一発でビルドできます:

```bash
cd book/code/chemcpp
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/parse_demo
```

> ⚠️ **正直な注記**: 本書のサンプルコードは、
> 執筆環境にC++コンパイラが無かったため**コンパイル検証をしていません**。
> 環境によっては小さな修正が必要かもしれません。
> そのときは[付録B コンパイルエラー辞典](appendix-b-error-dictionary.md)を
> 使ってください——エラーを読んで直すのも、C++学習の本質的な一部です。
