# 第2章 環境構築

Pythonなら `pip install` で終わる話が、C++では少し面倒です。
でも一度作れば数年使えます。30分だけ我慢してください。

## 2.1 必要なもの

| 道具 | 役割 | Pythonでの対応物 |
|---|---|---|
| **コンパイラ** | `.cpp` → 実行ファイル | CPython インタプリタ |
| **標準ライブラリ** | vector, string など | 標準ライブラリ（コンパイラに同梱） |
| **ビルドシステム (CMake)** | 複数ファイルのビルド手順を管理 | setup.py / pyproject.toml |
| **エディタ (VSCode)** | 補完・エラー表示 | VSCode / PyCharm |
| **デバッガ (gdb/lldb)** | ステップ実行 | pdb |
| **パッケージマネージャ** | ライブラリ導入（任意） | pip |

最初の3つがあれば始められます。

## 2.2 Windows

Windowsには2つの道があります。**迷ったら A を選んでください。**

### 選択肢A: MSYS2 + MinGW-w64（推奨・この本の標準）

Linux/macOSと**同じコマンド**（`g++`）が使えるので、本書のコマンドがそのまま通ります。

**手順:**

1. https://www.msys2.org/ からインストーラをダウンロードして実行
   （デフォルトの `C:\msys64` でOK）
2. スタートメニューから **「MSYS2 UCRT64」** を起動（MSYS2 MSYS ではない点に注意）
3. パッケージを更新:

```bash
pacman -Syu
```

（途中でターミナルが閉じたら、もう一度 UCRT64 を起動して再実行）

4. コンパイラ一式を入れる:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-gdb mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja
```

5. 確認:

```bash
g++ --version
cmake --version
```

6. **PowerShell/コマンドプロンプトからも使えるようにする**（重要）

環境変数 `Path` に `C:\msys64\ucrt64\bin` を追加します。

- Windowsキー → 「環境変数」で検索 → 「環境変数を編集」
- ユーザー環境変数の `Path` → 編集 → 新規 → `C:\msys64\ucrt64\bin`
- OK → **PowerShellを開き直す**

PowerShellで確認:

```bash
g++ --version
```

> ⚠️ `pacman -S mingw-w64-x86_64-gcc`（`ucrt` なし）という古い記事がありますが、
> 今は **UCRT版** を使うのが推奨です。Windowsの新しいCランタイムを使うため、
> ロケールや浮動小数点の挙動が素直になります。

### 選択肢B: Visual Studio 2022（MSVC）

Windows専用の本格開発や、Windows向け配布バイナリを作るならこちら。

1. https://visualstudio.microsoft.com/ja/downloads/ から
   **Visual Studio Community 2022**（無料）をダウンロード
2. インストーラで **「C++によるデスクトップ開発」** ワークロードにチェック
3. インストール（10〜20GB食います）

コンパイラを使うときは、スタートメニューの
**「x64 Native Tools Command Prompt for VS 2022」** から起動します。

```bash
cl /std:c++20 /EHsc /O2 hello.cpp
```

MSVC はコマンドラインオプションが `g++` と全然違います。対応表:

| 目的 | g++ / clang++ | MSVC (cl) |
|---|---|---|
| C++20を使う | `-std=c++20` | `/std:c++20` |
| 最適化 | `-O2` | `/O2` |
| 警告を多く | `-Wall -Wextra` | `/W4` |
| デバッグ情報 | `-g` | `/Zi` |
| 出力ファイル名 | `-o prog` | `/Fe:prog.exe` |
| 例外を有効化 | （デフォルト） | `/EHsc`（必須） |
| インクルードパス | `-I dir` | `/I dir` |
| ライブラリリンク | `-l名前` | `名前.lib` |

> 💡 CMake（第19章）を使えば、この違いはCMakeが吸収してくれます。
> 最初のうちだけコマンドを直接叩き、慣れたらCMakeに移行しましょう。

### 選択肢C: WSL2（Linux環境をWindows内に）

普段からPythonをWSLで動かしている人はこれが一番楽です。

```bash
wsl --install -d Ubuntu
```

起動後、Linuxの手順（2.3節）に従ってください。
VSCode の **WSL拡張**を入れると、Windows側のVSCodeからシームレスに編集できます。

> 🧪 RDKitのC++版を自前ビルドしたい場合（第27章）、WSL2かLinuxが圧倒的に楽です。
> Windowsネイティブでのビルドは Boost の依存で苦労します。

```bash
sudo apt update
```

```bash
# 使うとき: g++-13 -std=c++20 ...
```

```bash

```

### Fedora / RHEL系

```bash
sudo dnf install -y gcc-c++ gdb cmake ninja-build
```

### Arch

```bash
sudo pacman -S base-devel cmake ninja gdb
```

## 2.4 macOS

1. ターミナルを開いて:

```bash
xcode-select --install
```

これで Apple Clang（`clang++`）が入ります。`g++` コマンドも使えますが、
**中身はClang**です（Appleのエイリアス）。

2. Homebrew で CMake などを入れる:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install cmake ninja llvm
```

3. 確認:

```bash
clang++ --version
cmake --version
```

> ⚠️ **macOSの注意**: Apple Clang は C++20 の一部（`std::format` など）が
> 長らく未対応でした。本物のLLVM Clangを使いたい場合:
>
> ```bash
> brew install llvm
> export PATH="/opt/homebrew/opt/llvm/bin:$PATH"   # Apple Silicon
> # export PATH="/usr/local/opt/llvm/bin:$PATH"    # Intel Mac
> ```
>
> あるいは GCC を入れる:
> ```bash
> brew install gcc      # g++-14 などのコマンド名で入る
> ```

## 2.5 動作確認: 最初のコンパイル

任意のディレクトリで `hello.cpp` を作ります。

```cpp
// hello.cpp
#include <iostream>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> smiles = {
        "CCO",              // エタノール
        "c1ccccc1",         // ベンゼン
        "CC(=O)Oc1ccccc1C(=O)O"  // アスピリン
    };

    for (const auto& s : smiles) {
        std::cout << s << "  (length = " << s.size() << ")\n";
    }
    return 0;
}
```

コンパイルして実行:

```bash
g++ -std=c++20 -O2 -Wall -Wextra hello.cpp -o hello
./hello
```

Windows（PowerShell）なら:

```bash
g++ -std=c++20 -O2 -Wall -Wextra hello.cpp -o hello.exe
.\hello.exe
```

期待される出力:

```
CCO  (length = 3)
c1ccccc1  (length = 8)
CC(=O)Oc1ccccc1C(=O)O  (length = 21)
```

出たら成功です。おめでとうございます。

### コンパイルオプションの意味

| オプション | 意味 | いつ使う |
|---|---|---|
| `-std=c++20` | C++20の機能を有効化 | **常に** |
| `-O2` | 最適化レベル2 | 速度を測るとき、本番 |
| `-O0` | 最適化なし | デバッグ時（デフォルト） |
| `-g` | デバッグ情報を埋め込む | デバッガを使うとき |
| `-Wall -Wextra` | 警告を多めに出す | **常に** |
| `-Werror` | 警告をエラー扱いにする | CI、チーム開発 |
| `-o 名前` | 出力ファイル名 | 常に |
| `-march=native` | このCPU専用の命令を使う | 手元で速度を極めるとき |
| `-fsanitize=address` | メモリバグ検出 | デバッグ時（第29章） |

> 💡 **私のおすすめデフォルト**
>
> 開発中:
> ```bash
> g++ -std=c++20 -g -O0 -Wall -Wextra -fsanitize=address,undefined prog.cpp -o prog
> ```
> 速度計測・本番:
> ```bash
> g++ -std=c++20 -O2 -DNDEBUG -Wall -Wextra prog.cpp -o prog
> ```
>
> ⚠️ **`-O0` で速度を測ってはいけません。** 10倍遅い数字が出ます。
> 「C++にしたのに速くならない」の原因の第1位がこれです。

## 2.6 VSCode のセットアップ

Pythonで既にVSCodeを使っているなら、拡張機能を足すだけです。

### 入れる拡張機能

1. **C/C++**（Microsoft製、`ms-vscode.cpptools`）— デバッガと基本機能
2. **clangd**（`llvm-vs-code-extensions.vscode-clangd`）— **補完とエラー表示が段違い**
3. **CMake Tools**（`ms-vscode.cmake-tools`）— CMakeプロジェクトの管理

> 💡 C/C++拡張 と clangd はIntelliSenseが競合します。
> clangd を入れたら、C/C++拡張の設定で
> `C_Cpp.intelliSenseEngine` を `disabled` にしてください。
> **clangdの方が圧倒的に賢い**です（型推論、エラーメッセージ、リファクタリング）。

clangd 本体も必要です:

```bash
# Ubuntu
sudo apt install clangd-17
# macOS
brew install llvm
# MSYS2
pacman -S mingw-w64-ucrt-x86_64-clang-tools-extra
```

### 単一ファイルをF5でデバッグ実行する設定

プロジェクトフォルダに `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "shell",
      "label": "build",
      "command": "g++",
      "args": [
        "-std=c++20", "-g", "-O0", "-Wall", "-Wextra",
        "${file}",
        "-o", "${fileDirname}/${fileBasenameNoExtension}"
      ],
      "group": { "kind": "build", "isDefault": true }
    }
  ]
}
```

`.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug current file",
      "type": "cppdbg",
      "request": "launch",
      "program": "${fileDirname}/${fileBasenameNoExtension}",
      "args": [],
      "cwd": "${fileDirname}",
      "stopAtEntry": false,
      "externalConsole": false,
      "MIMode": "gdb",
      "preLaunchTask": "build"
    }
  ]
}
```

macOS なら `"MIMode": "lldb"`、`"type": "cppdbg"` のままでOKです。

これで `.cpp` ファイルを開いて **F5** を押すと、ビルドして
ブレークポイントで止まるようになります。

### clangd に「C++20を使え」と教える

単一ファイルをいじっているとき、clangd はデフォルトでC++17を仮定して
「この機能は C++20 が必要」と赤線を引くことがあります。
プロジェクトルートに `.clangd` ファイルを置いて解決:

```yaml
CompileFlags:
  Add: [-std=c++20, -Wall, -Wextra]
```

CMakeを使う場合は、後述の `CMAKE_EXPORT_COMPILE_COMMANDS` で自動解決されます。

## 2.7 CMake を使ったビルド（プレビュー）

ファイルが2つ以上になったら、コマンドを手打ちするのは限界です。
詳しくは第19章でやりますが、雰囲気だけ見ておきましょう。

`CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20)
project(chemcpp CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)   # clangd 用

add_executable(hello hello.cpp)
```

ビルド:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/hello
```

| コマンド | 意味 |
|---|---|
| `-S .` | ソースは現在のディレクトリ |
| `-B build` | ビルド成果物は `build/` に置く |
| `-G Ninja` | Ninja を使う（速い。無ければ省略可） |
| `-DCMAKE_BUILD_TYPE=Release` | 最適化ON（`Debug` なら `-g -O0`） |

> 🐍 **Pythonとの対比**
>
> `CMakeLists.txt` は `pyproject.toml` に相当します。
> 「どのファイルをまとめて、何という成果物にするか」を書く設定ファイルです。
> 違いは、Pythonがビルド不要なのに対し、C++は**必ずビルドが必要**なこと。

## 2.8 ライブラリの導入方法（後で必要になったとき）

Pythonの `pip install` に当たるものは、C++では**統一されていません**。
主要な選択肢:

| 方法 | 特徴 | おすすめ度 |
|---|---|---|
| **ヘッダオンリーライブラリを直接置く** | `.hpp` を1個コピーするだけ | ★★★（最も楽） |
| **CMake FetchContent** | CMakeがGitHubから自動DL | ★★★（本書の推奨） |
| **vcpkg** | Microsoft製。Windows向けに強い | ★★☆ |
| **Conan** | Python製パッケージマネージャ | ★★☆ |
| **システムのパッケージ管理** | `apt install libboost-dev` など | ★★☆（Linuxなら楽） |
| **conda / mamba** | RDKitなど科学系に強い | ★★★（既に使ってるなら） |

FetchContent の例（第19章で詳説）:

```cmake
include(FetchContent)
FetchContent_Declare(
  fmt
  GIT_REPOSITORY https://github.com/fmtlib/fmt.git
  GIT_TAG        11.0.2
)
FetchContent_MakeAvailable(fmt)

target_link_libraries(hello PRIVATE fmt::fmt)
```

これで `#include <fmt/format.h>` が使えるようになります。
`pip install fmt` に近い体験です。

> 🧪 **RDKit の C++ 版を入れたい人へ**
>
> 一番楽なのは conda です:
> ```bash
> mamba create -n rdkit-cpp -c conda-forge rdkit-dev cmake ninja cxx-compiler
> mamba activate rdkit-cpp
> ```
> `rdkit-dev` にはC++のヘッダとライブラリが入っています。第27章で使います。

## 2.10 トラブルシューティング

### `g++: command not found`

PATHが通っていません。Windowsなら 2.2 の手順6をやり直してください。
シェルを開き直すのを忘れがちです。

### `fatal error: iostream: No such file or directory`

C++の標準ライブラリが見つかっていません。
`gcc` ではなく **`g++`** を使っているか確認してください。
（`gcc` はCコンパイラとして動くので、C++標準ライブラリをリンクしません）

### `error: 'std::format' is not a member of 'std'`

コンパイラがC++20の `<format>` に未対応です。GCC 13+ / MSVC 19.29+ が必要。
代替として **fmt** ライブラリを使ってください（使い方はほぼ同じ）:

```cpp
#include <fmt/format.h>
std::string s = fmt::format("{} atoms", n);
```

### `undefined reference to 'main'`

`main` 関数がないか、綴りを間違えています。あるいは
ライブラリ用のファイルを実行ファイルとしてコンパイルしようとしています。

### `undefined reference to ...`（自作関数）

宣言だけして定義を書き忘れたか、複数ファイルのリンクを忘れています:

```bash
g++ -std=c++20 main.cpp molecule.cpp -o prog   # 両方渡す
```

詳しくは第3章と付録Bで。

### Windowsで実行ファイルが「DLLが見つかりません」と言う

MSYS2でビルドした実行ファイルは、MSYS2のDLLに依存します。
`C:\msys64\ucrt64\bin` にPATHを通すか、静的リンクしてください:

```bash
g++ -std=c++20 -O2 -static prog.cpp -o prog.exe
```

## 2.11 この章のまとめ

- Windows は **MSYS2 + UCRT64** が最も本書と相性がいい
- コンパイルの基本形は
  `g++ -std=c++20 -O2 -Wall -Wextra file.cpp -o prog`
- **速度を測るときは必ず `-O2`**。`-O0` の数字は無意味
- VSCode + **clangd** で、Pythonに近い快適な補完が得られる
- ファイルが増えたら CMake（第19章）
- 環境構築が面倒なら、まず **godbolt.org** で試すのもアリ

> 📝 **練習問題 2-1**
>
> 2.5 の `hello.cpp` を、`-O2` ありとなしでコンパイルして、
> 実行ファイルのサイズを比べてみてください。
>
> ```bash
> g++ -std=c++20 -O0 hello.cpp -o hello_O0
> g++ -std=c++20 -O2 hello.cpp -o hello_O2
> ls -l hello_O0 hello_O2
> ```

> 📝 **練習問題 2-2**
>
> godbolt.org を開き、以下を貼り付けて、右側の機械語を眺めてみてください。
> `-O0` と `-O2` を切り替えると何が起きますか?
>
> ```cpp
> int add(int a, int b) { return a + b; }
> int calc() { return add(3, 5); }
> ```
>
> （`-O2` では `calc` が `mov eax, 8` の1命令になるはずです。
> 関数呼び出しも足し算もコンパイル時に消えました）
